# EDA — 데이터 구조와 "분석을 설계할 때 조심할 것"

- 데이터: dunnhumby *The Complete Journey* — 미국 식료품 리테일러의 가구 2,500곳, 2년(711일) 전 거래
- 이 문서의 목적: 테이블 나열이 아니라, **분석 설계를 바꾸게 만드는 사실**들을 근거와 함께 남기는 것
- 모든 수치 재현: `sql/00_build_base_layer.py` 실행 후 각 스크립트 (DuckDB)

## 2. 분석 설계를 바꾸는 사실 5가지

### (1) 시간축이 상대값이다
DAY 1~711, WEEK 1~102만 있고 달력 날짜가 없다. → 계절성(명절·연말) 해석 불가, 가입월 코호트 불가. 코호트는 "첫 구매 주차" 기준 유사-코호트로만.

### (2) 패널이 서서히 차오른다 (좌측 절단·램프인)

![주차별 활동 가구](../figures/eda1_weekly_households.png)

주차별 활동 가구가 1주차 88 → 5주차 370 → 이후 약 1,250 수준. 관측 초기의 "첫 구매"는 신규 가입이 아니라 **패널 편입**일 가능성이 높다. → 초기 ~10주는 리텐션·코호트 분석에서 별도 취급. 전 기간 기준 F(방문수)·M(지출)은 "고객 생애 규모"가 아니라 "관측 기간 내 활동량"이다.

### (3) 캠페인 30개는 전부 DAY 224 이후 시작하고, 서로 촘촘히 겹친다

![캠페인 타임라인](../figures/eda2_campaign_timeline.png)

- 좋은 소식: 모든 캠페인에 최소 224일의 사전 기간 → 사전-사후 비교가 성립
- 나쁜 소식: 활성 기간이 겹쳐서 같은 가구가 동시에 여러 캠페인을 받는다 → "이 캠페인의 전후"를 보려면 다른 캠페인과 겹치지 않는 창만 남겨야 함 (실제로 남는 건 수신 쌍의 18.4% — 가설 검증 문서 참고)

### (4) 인구통계는 32%만 있고, 그마저 우량 가구 쪽으로 치우쳐 있다

![인구통계 편향](../figures/eda3_demo_bias.png)

hh_demographic이 있는 801가구는 평균 지출 $5,096 vs 없는 가구 $1,946 (2.6배). → 소득/연령 세그먼트 분석은 "전체 고객"이 아니라 **우량 편향 부분집합** 분석임을 반드시 병기. 세그먼트의 1차 축으로는 인구통계 대신 행동 지표(RFM)를 쓰는 근거.

### (5) 반품 행이 없다 — 대신 다른 함정이 있다
음수 수량/금액 행이 0건이라 "반품 제외" 전처리는 불필요. 대신:
- QUANTITY=0 행 14,466개 (매출 합계 $19 — 할인 조정 기록으로 추정)
- `COUPON/MISC ITEMS`·`FUEL` 커모디티의 극단 수량 (주유 키오스크, 최대 89,638 — 수량 단위가 다름)
- RETAIL_DISC에 양수 36행 (데이터 오류, 최대 $3.99)
- 할인 컬럼(RETAIL/COUPON/COUPON_MATCH_DISC)은 **음수로 저장** — 집계 시 부호 주의

## 3. 그래서 만든 것 — 베이스 레이어 (transactions_base)

위 함정들을 매번 각자 처리하지 않도록 정제 테이블을 하나 만들었다. **이후 모든 분석은 raw가 아니라 transactions_base만 사용.**

| 제외 규칙 | 행수 | 매출 | 근거 |
|---|---:|---:|---|
| E1: QUANTITY=0 | 14,466 | $19 | 99.5%는 매출도 0 |
| E2: COUPON/MISC ITEMS | 27,710 | $639,878 | 주유 키오스크·잡수입 — 상품 구매 아님 |
| E3: FUEL | 1,788 | $29,537 | 수량이 연료 부피 단위 |
| 합계 | 43,964 (1.7%) | $669,434 (8.3%) | |

- 보정: 양수 RETAIL_DISC 36행은 0으로 클램프
- 빌드 시 자동 sanity check 5종(행수·매출 회계, 기간·가구 보존) 전부 통과
- 해석 주의: 제외 매출의 96%가 주유라서, transactions_base의 매출은 "**식료품 상품 매출**"이다 (가구 총지출 아님)

## 4. 표본이 얇아서 조심할 곳

- 쿠폰 상환 가구 434곳 — 캠페인×세그먼트×기간 다중 세분화는 셀이 금방 빈다. 분석 축 2개 이하 권장
- causal_data(진열/전단)는 매장 115개(20%)만 커버 — 전사 일반화 불가, 부분집합 분석으로만
- coupon은 쿠폰↔상품 다대다(쿠폰당 평균 99개 상품, 최대 14,477) — 거래에 바로 조인하면 행 폭발. 축약 후 조인

## 5. 분석 공유 전 셀프체크 5문항

| 지점 | 스스로에게 물어볼 것 |
|---|---|
| 모집단 | raw를 직접 집계했는가? → transactions_base만 사용 |
| 집계 단위 | 결과의 행 하나가 무엇인가 — 가구? 방문(가구×일)? 바스켓? 상품 행? |
| 조인 | coupon/causal_data를 축약 없이 조인하지 않았는가? |
| 커버리지 | hh_demographic(32%)·causal_data(매장 20%)를 썼다면 "부분집합 분석" 병기했는가? |
| 비교 설계 | "수신 가구가 더 샀다"식 비교를 하지 않았는가? (수신 자체가 타겟팅 결과 — 4.3배 편향 실측) |

그리고 인사이트 문장 하나당 한 번: **"숫자가 반대로 나왔어도 쓸 수 있는 문장인가?"**
